### Policy Types Explanation

ATProto Spaces use a **policy union** system. When you create or update a space, you must specify one of three policy types that govern how the space operates:

#### 1. `com.atproto.personalspace.policy`
- **Purpose**: Owner-only spaces
- **Behavior**: Only the space owner can read/write
- **Configuration**: Empty definition (no options)
- **Use case**: Private personal data storage

#### 2. `com.atproto.memberspace.policy`
- **Purpose**: Group/collaborative spaces with membership
- **Configuration options**:
  - `publicRead` - Whether non-members can read
  - `publicWrite` - Whether non-members can write
  - `allowedApps` - List of app DIDs allowed to access
  - `publishPolicy` - Whether to publish the policy record
  - `publishMembers` - Whether to publish the member list
- **Additional endpoints**: `com.atproto.memberspace.{putMember, removeMember, listMembers}`
- **Use case**: Group chats, collaborative projects, communities

#### 3. `com.atproto.managedspace.policy`
- **Purpose**: App-managed spaces (no user members)
- **Configuration options**:
  - `managingApp` - The app DID that controls access
  - `publishPolicy` - Whether to publish the policy record
- **Additional endpoints**: `com.atproto.managedspace.checkUserAccess`
- **Use case**: App-controlled data, game state, app-specific storage
- **Note**: `putMember`, `addMember`, `createInvite`, `acceptInvite` are refused with `InvalidRequest`

## Message 22 - Assistant

Yes, that's correct. With a custom `MarshalJSON` method, both the `Type` field and `NewPolicy` function would become unnecessary:

**Current Design:**
```go
type Policy struct {
    Type          string `json:"$type,omitempty"`  // can be set incorrectly
    ManagingApp   string `json:"managingApp"`
    PublishPolicy bool   `json:"publishPolicy,omitempty"`
}

func NewPolicy(managingApp string) Policy {
    return Policy{
        Type:        "com.atproto.managedspace.policy",
        ManagingApp: managingApp,
    }
}
```

**Refactored Design:**
```go
type Policy struct {
    ManagingApp   string
    PublishPolicy bool
}

func (p Policy) MarshalJSON() ([]byte, error) {
    type wire struct {
        Type          string `json:"$type"`
        ManagingApp   string `json:"managingApp"`
        PublishPolicy bool   `json:"publishPolicy,omitempty"`
    }
    return json.Marshal(wire{
        Type:          "com.atproto.managedspace.policy",
        ManagingApp:   p.ManagingApp,
        PublishPolicy: p.PublishPolicy,
    })
}
```

**Benefits:**
1. Users can't accidentally set wrong $type
2. No need for constructor - just use struct literal
3. Cleaner public API
4. Consistent with personalspace.Policy approach

This same pattern could be applied to `memberspace.Policy` as well for consistency across all three policy types.

### Summary of Pattern

```go
const NSID string = "com.atproto.{namespace}.policy"

type Policy struct {
    // Fields without JSON tags
}

type policyWireFormat struct {
    Type string `json:"$type"`
    // Fields with JSON tags
}

func (p Policy) MarshalJSON() ([]byte, error) {
    return json.Marshal(policyWireFormat{
        Type: NSID,
        // Copy fields
    })
}

func (p *Policy) UnmarshalJSON(data []byte) error {
    var wire policyWireFormat
    if err := json.Unmarshal(data, &wire); err != nil {
        return fmt.Errorf("...: failed to unmarshal: %w", err)
    }
    if wire.Type != NSID {
        return fmt.Errorf("...: unexpected $type: got %q, want %q", wire.Type, NSID)
    }
    // Copy fields back
    return nil
}
```

**Benefits:**
1. Users cannot set incorrect `$type` values
2. No constructor functions needed - use struct literals directly
3. Consistent API across all policy types
4. Automatic validation on unmarshal
5. Clean error messages with context
